# Generalize PIN-gated secret-ID encryption, responsive grid, and dark-theme polish

Generalizes the existing SSN pattern (AES-256-GCM encrypt-at-rest + PIN-gated reveal + masked last-4) to driver's license, Safety Council ID, and TWIC number; freezes the grid's Employee column and adds a mobile card view to kill left-right scroll; and extracts shared dark-theme tokens plus a `StatusPill`. The approach is strictly additive: a new `revealField` reuses the SSN reveal's exact 3-part gate, a new `encField` mirrors `encSsn` with a FIX5 idempotency guard, and the former `SsnField`/`SsnEditCell` become reusable `SecretField`/`SecretEditCell` driven by a `SecretFieldKey`. All four FEATs are marked completed; `npx tsc --noEmit` and `npm run build` are both green, and the migration script is idempotent on re-run.

Watch for: the branch has diverged from `master` — 19 master commits (including an employee-import *update* branch, travel requests, PWA, timesheet export) are not on this branch (**confirmed**). This is an integration concern, not a task defect, but whoever merges must re-apply `encField` to any import update path master introduced.

**Verdict**: APPROVED

## High-level view

The crypto layer gains `maskLast4` (holding the former `maskSsn` body verbatim, so SSN masking is unchanged) and `encField`, whose first line is the FIX5 idempotency guard that passes an already-`enc:v1:` value straight through. `encSsn` is now a thin wrapper. No existing primitive was touched.

Reveal authorization is unchanged in strength: `revealField` reproduces the SSN gate exactly — per-field `canView`, then `canFullView` (library/assignment/grant), then the non-admin site restriction — before a HARD `decryptSecret` that maps any failure to `DECRYPT_FAILED` so a corrupt row never silently shows plaintext. The dynamic column read uses a literal-key `satisfies Prisma.EmployeeSelect` select (FIX2), avoiding the computed-key widening trap.

No raw or ciphertext secret reaches a client component. Every `SecretField`/`SecretEditCell` is handed only a server-computed `maskSsn(...)`/`maskLast4(safeDecrypt(...))` string plus `employeeId`, `field`, and `canReveal`; the reveal is always a fresh server round-trip. The masked value and the eye render only inside the same per-field `canView` guard, so a role that cannot view a field sees `—` and no eye (FIX4).

Writes go through dedicated PIN-gated actions dispatched by field (FIX3): a DL save routes through `setEmployeeDriversLicense`, never the SSN column. Onboarding submit/draft and the Excel import encrypt the three IDs with `encField` at their write points; the onboarding prefill `safeDecrypt`s them so a resubmit can't double-encrypt. The invoices CSV masks the DL column (FIX2) and never emits ciphertext.

The grid builds every cell once via `buildRow` and feeds both the frozen-column table (sticky `left-0`, opaque background, inset-ring approved highlight, right-edge shadow) and the `md:hidden` card list from identical nodes, so functionality is preserved across both views. The dark-theme pass is className/markup only — the FEAT-004 commit changed no action, redirect, or access-check line.

### Reveal gate is additive and fails closed

`revealField(pin, employeeId, field)` runs `requirePin` first, then rebuilds the detail page's composite gate in order: `canView(access, viewKey)` for the field, then `canFullView = canLib || isAssignedProjectLeadOrManager || granted`, then — for non-admins with assigned sites — a site-membership check. A missing employee returns `FORBIDDEN` (no existence leak). The decrypt is HARD: `decryptSecret(stored)` inside a try/catch that logs only the row id and field (never the value or ciphertext) and returns `DECRYPT_FAILED`. The `FIELD_MAP` ties each field to both its column and the same rbac view-key the display uses, so the reveal gate can never exceed display gating (**confirmed**).

The FIX2 select lists all four secret columns plus `site`/`projectLeadEmail`/`projectManagerEmail`/`createdById` with literal keys under `satisfies Prisma.EmployeeSelect`, then reads `e[column]` directly — the result type stays narrowed, which the FEAT-001 findings correctly identified as the reason a computed-key select fails to type-check (**confirmed**).

### No secret crosses the client boundary

A grep confirms every `maskedValue` prop in the tree is fed by `maskSsn(...)` or `maskLast4(...)` — never a raw column (**confirmed**). `SecretField`/`SecretEditCell` receive only the masked string, `employeeId`, `field`, `label`, and `canReveal`; the full value exists on the client only transiently in reveal state after a server round-trip, and clicking again drops it. The grid search decrypts SSN and DL in server scope solely to build a match token and never writes the plaintext back onto the row objects handed to client cells (**confirmed**).

### Per-field guard tightening does not widen visibility (FIX1)

On the detail page the entire Details `<dl>` is inside `{canFullView && (...)}`, and each secret row is additionally wrapped in its own `canView` guard (`driverLicense`, `safetyExpiry`, `twicExpiry`, `ssn`), with `canReveal` set to the same guard. Because the section already sits behind `canFullView` and the per-field keys match the keys that gate the corresponding grid columns, this tightens rather than widens — no role gains visibility of a field it could not already see, and SAFETY never reaches the section (**confirmed**). `maskLast4(safeDecrypt(...))` means a legacy/corrupt row masks to `—` without throwing.

### Field-dispatched writes (FIX3)

`SecretEditCell` dispatches save/clear via `WRITE_ACTION = { ssn: setEmployeeSsn, driversLicense: setEmployeeDriversLicense }` and bails with "Not authorized" if a field has no mapped action, so a DL write can never travel through the SSN column. `setEmployeeDriversLicense` is byte-for-byte `setEmployeeSsn` with `driverLicense`: `requireColumn("driverLicense","edit",id)`, `checkPin`, empty-save-no-op, explicit clear → `{ driversLicenseNumber: null }`, else `{ driversLicenseNumber: encField(value) }` (**confirmed**). The legacy `setEmployeeField` `driverLicense` case still writes plaintext, but the grid never routes a DL *value* write through it — `EditableCell` is used only for name/email/phone/dates/address, and the DL cell's `UploadCell column="driverLicense"` is a document upload, not a field write — so the dead case is unreachable from the grid (**confirmed**).

### Idempotent encryption everywhere a secret is written

`encField`'s first line, `if (typeof value === "string" && isEncrypted(value)) return value;`, is the FIX5 backstop (**confirmed**). Onboarding `submitOnboarding` and `saveOnboardingDraft` both wrap the three IDs in `encField` and keep SSN on `encSsn`; the expiry DATE fields stay plaintext. The onboarding page prefill `safeDecrypt`s the three IDs (and SSN) before handing them to the form. The Excel import encrypts `driversLicenseNumber` with `encField` at its single `createMany` write point — `safetyCouncilId`/`twicNumber` are not import columns in this worktree, matching the context notes, and the comment flags that a future update branch must encrypt too (**confirmed**).

The standalone `scripts/encrypt-id-fields.cjs` mirrors the SSN script: same AES-256-GCM scheme and `enc:v1:` prefix with the 12-byte IV / 16-byte tag layout matching `crypto.ts`, reuses `SSN_ENCRYPTION_KEY` (with the `.env` fallback, never generating a key), skips empty and already-encrypted values, and logs counts only (row id on per-row failure). Running it twice reported "Encrypted 0, skipped 3" both times — idempotency confirmed against the live DB (**confirmed**).

### Invoices CSV masks the DL column (FIX2)

The `driverLicense` case in `employeeFieldValue` returns `maskSsn(safeDecrypt(e.driversLicenseNumber))`, reusing the already-imported `maskSsn` (which delegates to `maskLast4`), so the persisted CSV carries only the masked last-4 and never ciphertext; the SSN case was already masked. The surrounding `csvField` still applies formula-injection escaping (**confirmed**).

### Responsive grid preserves functionality in both views

`buildRow(e)` constructs the name node and an ordered `RowCell[]` once, pushing a cell only when `show(key)` is true, so the same cell components with identical `field`/`label`/`canReveal` feed both views; only the wrapping markup (`<td>` vs `<dt>/<dd>`) differs. The table container is `hidden ... md:block` and the card list is `md:hidden` — mutually exclusive at 768px. The frozen Employee column uses `sticky left-0` with an opaque `bg-slate-900`, explicit z-layering (corner 30 > header 20 > frozen body 10), and a right-edge shadow; because the opaque background hides the row's `bg-emerald-500/10`, the approved highlight is re-expressed on the frozen cell via `ring-inset ring-1 ring-emerald-500/30`. Both views are mounted at once, which is safe only because `SecretField`/`SecretEditCell` have no mount-time side effect — the FIX4 comment in both components documents this constraint (**confirmed**). A live pixel confirmation of scroll feel was not possible (no headless-browser tooling in this repo); verification is via the emitted breakpoint/sticky classes plus a green build.

### Dark-theme pass is restyle-only

`src/lib/ui.ts` (class-string tokens) and `StatusPill.tsx` (markup-only server component) are new. `PinDialog` adopts the tokens and gains a lock badge, centered large PIN input, and gradient confirm button while keeping its exact contract (`open/onConfirm/onCancel/title/description`), the NO_PIN → `/admin/profile#pin` setup CTA, and accessibility (`role="dialog"`, `aria-modal`, `aria-label`, focus-on-open). The FEAT-004 commit's changed lines contain no `action=`, `redirect(`, `canView/canEdit/canApprove`, `prisma.`, or `revalidatePath` edits; the only grid change is swapping the non-interactive approved/pending span for `StatusPill` (the interactive approve form is untouched) (**confirmed**).
